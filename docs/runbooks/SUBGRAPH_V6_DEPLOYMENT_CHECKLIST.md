## Post-Deployment Verification

### Sync Status Check

Wait for subgraph to sync to recent blocks:

```bash
# Query subgraph health
curl -X POST https://api.goldsky.com/subgraphs \
  -H "Content-Type: application/json" \
  -d '{"query": "{ _meta { block { number } } }"}'
```

**Expected**: Block number close to current Celo block height

### Test Query 1: Basic Leaderboard

```graphql
query {
  players(first: 5, orderBy: xp, orderDirection: desc) {
    id
    username
    xp
    gamesPlayed
    totalGSpent
  }
}
```

**Expected**: Returns top 5 players by XP; all fields populated

### Test Query 2: New Fields (Undo Credits)

```graphql
query {
  players(where: { undoCreditsPurchased_gt: 0 }, first: 5) {
    username
    undoCreditsPurchased
    totalGSpent
  }
}
```

**Expected**: Returns players with undo purchases (may be empty if no V6 purchases yet)

### Test Query 3: Cosmetics Ownership

```graphql
query {
  players(where: { cosmeticsOwned_not: [] }, first: 5) {
    username
    cosmeticsOwned
  }
}
```

**Expected**: Returns players with cosmetics (may be empty if no V6 purchases yet)

### Test Query 4: Event Coverage

```graphql
query {
  players(first: 10, orderBy: lastUpdated, orderDirection: desc) {
    id
    username
    lastUpdated
    xp
    totalGSpent
    totalGEarned
  }
}
```

**Expected**: All players have recent `lastUpdated` timestamps; all fields present

### Test Query 5: Full Leaderboard

```graphql

  players(first: 25, orderBy: xp, orderDirection: desc) {
    id
    username
    xp
    gamesPlayed
    bestScore
    totalGEarned

    cosmeticsOwned
    referralCount
  }
}
```

**Expected**: All fields present; V3 schema working correctly

## Go/No-Go Decision

### Green Light (Promote to Production)

✅ All boxes below checked:

- [ ] Staging subgraph fully synced
- [ ] No indexing errors in logs
- [ ] All test queries pass
- [ ] Data accuracy validated (spot checks)
- [ ] Response times acceptable
- [ ] No regressions in existing fields
- [ ] New fields correct and working
- [ ] Frontend team confirms compatibility
- [ ] Stable for 24+ hours without issues

**Action**: Promote `blockslide-leaderboard-staging/3.0.0` → `blockslide-leaderboard/3.0.0` on Goldsky

### Red Light (Do Not Promote)

❌ Any of these apply:

- [ ] Sync stuck or behind current blocks
- [ ] Indexing errors in logs
- [ ] Query errors (500, syntax, etc.)
- [ ] Data appears corrupted or inconsistent
- [ ] Missing or null fields unexpectedly
- [ ] Response times degraded
- [ ] New handlers not firing
- [ ] Regressions in old handlers

**Action**: Investigate root cause; do not promote. Staging remains separate.

## Rollback Plan (If Issues After Production Promotion)

**Option 1: Revert to V1 (Safest)**
- Use Goldsky dashboard to point back to v1.0.0
- Old endpoint remains available
- No data loss

**Option 2: Keep V3, Fix Issue**
- Debug in staging
- Redeploy V3 to production with fix
- Requires root cause analysis first

**Option 3: Run V1 + V3 in Parallel**
- Keep both endpoints available
- Gradual frontend migration to V3
- Decommission V1 after all consumers migrated
